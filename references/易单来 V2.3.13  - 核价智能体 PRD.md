### 1. 需求范围与目标用户

本文档旨在定义“在线核价工具”的产品需求。该工具旨在通过标准化、自动化的成本与价格计算，提升核价效率与准确性。

#### 1.1 需求范围

*   **基础配置**：完善核价所需的基础数据，如原纸价格、加工费标准、原纸利用率等。
    
*   **核价功能**：支持基于标准公式的快速、精准核价。
    

#### 1.2 目标用户分析

| **用户角色** | **核心需求与使用场景** | **典型用户** | **使用频次** |
| --- | --- | --- | --- |
| **业务员** | 1.客户下单新材质时，能快速地给客户进行报价 | 漳州业务员 | 每天 |
| **销售管理**​ | 1.快速、准确地向业务员/客户报价。<br>2.审核业务员提交的特价申请，需要快速核算差价并评估是否批准。 | 温州张爱芳、宿州玉狼等 | 每天 |
| **区域运营**​ | 1.因原材料价格或市场策略变动，对大量已上架的产品进行集中核价。总经理下达指令涨价，运营执行，团长通知，业务员触达客户。<br>维护和更新核价所需的基础数据，如原纸价格等。  <br>2. 为新上架的材料核价。 | 金华桃凤、温州秀秀等 | 高频（日均几十至上千款） |

### 2. 解决的问题与需求目标

#### 2.1 核心解决的问题

1.  **工具分散低效**：依赖线下Excel等多种工具，数据传递和核对工作量大，易出错。
    
2.  **人工计算不清晰**：无法快速、清晰地记忆每个材质对应的原纸成本、加工价订单，计算错误理论成本底价和利润空间，不利于客户沟通。
    

#### 2.2 需求目标

| **指标** | **目标描述** |
| --- | --- |
| **效率提升**​ | 将单次核价操作时间从分钟级缩短至秒级；批量核价效率提升80%以上。 |
| **计算准确率**​ | 确保核价计算准确率达到100%，杜绝人为计算错误。 |
| **流程标准化**​ | 建立统一的线上核价流程，确保核价规则的规范执行。 |

### 3. 产品方案概述

#### 3.1 核心业务流程

1.  **初始化**：管理员在【成本配置、核价配置】模块维护核价所需的基础成本数据。
    
2.  **数据输入**：用户在界面中输入核价所需材质信息。
    
3.  **核心计算**：用户执行计算，系统根据预设规则自动完成核价。

### 4. 关键业务规则与说明

#### 4.1 价格计算规则

*   **牌价=（原纸成本+加工费+运费+返利成本）\*折扣**
    
*   **一口价=（原纸成本+加工费+运费）\*折扣**
    
*   **原纸成本=【SUM(****各层原纸价格\*对应瓦楞系数）/原纸利用率配置****】**
    
*   **单平方原纸价格=原纸吨价\*克重/1000000**
    
*   **返利成本=****（原纸成本+加工费+运费）****/（1-返利比例）\*返利比例**
    

#### 4.2 计算要素说明

*   **原纸成本**：可根据场景选择“库存单价”或“市场单价”等不同口径进行计算。
    
*   **加工费**：根据订单的“用料代码”自动匹配对应的层数、面纸，并获取预设的加工费。
    
*   **含税口径**：系统中所有金额类数据均默认为含税口径，确保财务计算一致性。

| 销售运营 | 按权限 | 有 | 无 | 无 | 无 | 有 |

权限规则：

1.  页面入口、按钮、字段和数据范围均由服务端权限控制，前端隐藏不能替代接口鉴权。

### 6. 术语表

为便于项目组成员统一理解，对本PRD中出现的专业术语进行说明：

| **术语** | **解释** |
| --- | --- |
| **核价**​ | 指根据产品的原材料成本、加工费用等要素，计算出一个建议销售价格的过程。 |
| **原纸成本**​ | 指生产纸制品所需原纸的采购成本。在本系统中，可根据不同场景选择“市场价”、“库存价”等不同口径。 |
| **楞型**​ | 指瓦楞纸板中间波浪形的楞纸类型，如A楞、B楞、C楞等，不同楞型影响产品的强度和成本。 |
| **楞率系数**​ | 一个计算用参数，指原纸在压楞后长度的延长比例，用于准确计算原纸的实际耗用量。 |
| **加工费**​ | 指与产品生产数量直接相关的加工成本，如人工、能耗等。通常按单位面积来计量。 |
| **返利** | 针对客户设定的返利比例，根据销售金额进行一定比例的金额返还。在核价时会提前将该部分纳入成本项，提高定价； |
| **折扣** | 部分市场没有返利，直接给客户在销售价上进行折扣优惠 |
| **销售价** | 指基于当前成本数据计算出的最低销售价格，低于此价格将导致亏损。是业务员报价的风险底线。 |

##### 7.2.3 材料代码输入与解析

| 项目 | 规则 |
| --- | --- |
| 输入方式 | 支持连续字符输入；仅支持英文和数字输入<br>支持根据历史核价记录进行模糊匹配； |
| 大小写识别 | 原纸代码同个英文字母，无论大小写都需要能支持匹配上； |
| 层数识别 | 每个字符或每2个字符代表一层原纸；（根据层数和字符个数自动判断） |
| 最小层数 | 至少 2 层 |
| 支持层数 | 2～7 层，是否可核价由供应商启用的楞型组合决定 |
| 解析预览 | 展示层角色、原纸代码、原纸类型+克重；例如“面纸：L   牛卡80g”<br>瓦纸选择楞型后，会展示对应瓦楞及系数； |
| 未匹配纸码 | 对未匹配代码标红；禁止核价并提示具体代码 |

材料代码变更后，系统清空已选楞型、旧核价结果、竞对匹配和待提交审批数据，并重新匹配加工费。

##### 7.2.4 层角色识别

1.  奇数层纸板：偶数位次为瓦纸，其余为非瓦纸。
    
2.  偶数层纸板：奇数位次为瓦纸，其余为非瓦纸。
    
3.  仅有奇数层有面纸，且第一层非瓦纸为面纸，最后一个非瓦纸为里纸，中间层为中隔纸。
    
4.  瓦纸按出现顺序映射楞型组合中的字母。例如 `BC` 组合中，第一个瓦纸使用 B 楞，第二个瓦纸使用 C 楞。
    

##### 7.2.5 楞型组合选择

1.  系统根据识别层数，展示后台核价配置的楞型选项。
    
2.  必须选择一个楞型组合后才可核价，未选择则toast提示：请选择楞型
    
3.  选择楞型后，解析预览实时更新瓦纸层的楞型和系数。
    
4.  若当前层数没有楞型组合，展示“暂无可用楞型组合，请联系管理员配置”，并禁止核价。
    
5.  已产生结果后切换楞型，需重新核价才生成核价结果，生成新的历史快照。

##### 7.2.7 核价校验

点击“开始核价”时依次校验：

1.  材料代码非空且层数≥2；
    
2.  所有原纸代码均已匹配；
    
3.  已选择有效楞型组合；
    
4.  加工费、利用率和公式配置有效；
    
5.  返利、折扣和其他费用均在允许范围内；
    
6.  校验用户的角色，若用户不在核价配置-使用角色配置的成员中，则toast提示：未配置后台使用角色，无法核价；
    

校验失败时保留用户输入，在对应字段附近显示原因，不创建历史记录。

#### 7.3 核价结果与成本明细

![image.png](https://alidocs.oss-cn-zhangjiakou.aliyuncs.com/res/YvenvegLzXWAMloy/img/170dda9c-d8f4-4284-b008-8f01261274dc.png)

##### 7.3.1 结果展示

1.  无返利时，主结果展示销售底价；有折扣时同时展示折扣前价格和最终价格。
    
2.  有返利时，分别展示牌价（含返利）和一口价（不含返利）；有折扣时分别展示折扣后的价格。
    
3.  所有对外报价保留两位小数并显示单位“元/㎡”。包括瓦纸成本乘上楞率后，也需四舍五入保留2位小数；
    

##### 7.3.2 成本明细

明细默认展开，点击：

1.  每层原纸仅展示原纸代码、单平方成本（UI调整）。原纸单平方成本根据供应商端-核价配置-角色核算价格选择的价格进行展示；**单平方原纸价格=原纸吨价\*克重/1000000；**若原纸价格页面中，原纸价格标签为“不含税”，则需要将原纸价格\*1.13；
    
2.  瓦纸的楞率取自核价配置-按角色的楞率配置进行计算；
    
3.  原纸成本合计、含利用率原纸成本。利用率取核价配置中该角色配置的原纸利用率进行计算；
    
4.  加工费、运费、基础小计、返利金额
    
5.  基于成本项得出销售底价（或牌价、一口价），再减去折扣金额得出最终价格。
    

无成本明细权限的用户隐藏成本明细，仅展示最终核算价格；

##### 7.5.2 提交流程

1.  若审批总开关关闭，则隐藏提交审批按钮；
    
2.  若审批总开关开启，用户点击“提交审批”，系统校验价格和审批配置。则按当前有效节点创建审批任务，状态为“待审批”。
    
3.  审批开启但没有有效节点时禁止提交，并toast提示：审批节点配置不全，请联系管理员完善。

5.  防止重复提交：同一核价记录（**同材质、客户、同类型价格、提交人**）已有待审批任务时，再次点击提交toast提示：已存在同材质审批，请勿重复发起；

##### 7.6.3 审批操作

1.  当前审批人可选择“通过”或“驳回”。
    
2.  审批通过：审批意见选填；审批支持在提交价格上继续调整，调整范围没有限制；需记录调整后价格。调整价格后，显示反算的加工费，公式同提交审批时调价，用审批人的成本计算；（UI调整）
    
3.  审批驳回：驳回原因选填；驳回后整个流程结束，不再流转后续节点。状态变为“已驳回”；
    
4.  通过当前节点后进入下一有效节点；全部有效节点通过后状态变为“已通过”。
    
5.  已结束或非当前节点审批不得重复操作；并发处理时以后端首次成功结果为准。
    

#### 7.7 AI审批价格建议（先不做）

1.  AI 建议只在审批详情和通过确认页展示，不直接替代审批人决策。
    
2.  输入数据至少包含：客户上月下单量、上月毛利额、平均毛利率、上月订单数、本单订单量、当前报价和理论底价。
    
3.  输出包含建议审批价格、相对当前报价的调整值、定价理由、关键指标和数据截止时间。
    
4.  审批人可一键采用建议价格，也可手动修改；最终选择必须留痕。
    
5.  缺少客户、订单或毛利数据时展示“数据不足，暂无法生成可靠建议”，不得使用随机数补齐。
    
6.  AI 建议不可突破系统配置的价格边界；价格边界具体口径待产品与财务确认。
    
7.  AI 调用失败不阻断人工审批，页面保留人工通过/驳回能力并记录失败原因。
