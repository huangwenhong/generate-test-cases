## 用户端

### 待办消息

#### 易付通还款通知

- **tc-P0-功能测试：易付通还款通知_情况一（支付失败）_触发条件与接收人（正常）**
        - PC:1、测试环境易网数据已就绪；
2、存在当日为还款日且余额未扣款、已绑定业务员的客户账单（覆盖单供应商、联合销售主体各一例）；
3、对应绑定业务员账号可登录用户端→待办消息。
  - **到达测试环境每日 8 点定时任务执行时点**
          - 定时任务正常执行，通知由当日 8 点任务产生，生成时间正确

  - **使用绑定业务员账号打开待办消息**
          - 生成该客户的易付通还款通知，接收人与该客户的绑定业务员关系一致

  - **使用同供应商但未绑定该客户的业务员乙账号打开待办消息**
          - 没有收到通知

  - **使用联合销售主体绑定业务员账号打开待办消息**
          - 该业务员收到对应客户的还款通知

- **tc-P0-功能测试：易付通还款通知_情况一（支付失败）_更换业务员后不收到通知（正常）**
        - PC:1、存在当日为还款日且余额未扣款、已绑定业务员的客户账单；
2、相关业务员账号可登录。
  - **更换业务员，扣款成功账单对应任务完成后查看待办**
          - 前业务员没有收到通知，新业务员收到通知

- **tc-P0-功能测试：易付通还款通知_情况一（支付失败）_当日多笔到期汇总发一条（正常）**
        - PC:1、同一客户同日有多笔到期未扣款记录，已登记各笔应通知金额；
2、客户绑定业务员账号可登录。
  - **等待当日 8 点任务执行完成**
          - 任务正常完成

  - **按该客户与当日日期检索待办消息**
          - 仅生成一条易付通还款通知

  - **汇总当日各笔应通知金额并与通知金额比对**
          - 通知金额等于当日各笔记录的合计

- **tc-P0-功能测试：易付通还款通知_情况一（支付失败）_不触发与部分扣款边界（异常/边界）**
        - PC:1、分别准备还款日已全额扣款成功的账单、符合情况一但未绑定业务员的客户、到期仅扣取部分金额仍有未扣余额的账单；
2、相关业务员账号可登录。
  - **扣款成功账单对应任务完成后查看待办**
          - 不发送通知

  - **未绑定业务员客户任务完成后检查发送记录与其他待办**
          - 该客户不发送还款通知，通知不转发给未绑定该客户的人员

  - **部分扣款账单任务完成后查看绑定业务员待办**
          - 1、部分扣款按“付款失败”处理，触发情况一通知；
2、金额取值汇总剩余未还款金额

- **tc-P0-功能测试：易付通还款通知_情况一（支付失败）_模板文案支付宝付款失败（UI）**
        - PC:1、准备已发送的情况一通知及对应未扣款账单；
2、接收业务员账号可登录。操作入口：用户端→待办消息→易付通还款通知。
  - **打开该情况一通知查看正文状态文案**
          - 正文金额及文案“支付宝付款失败”，以蓝色强调

  - **核对正文整体模板**
          - 正文为“你的客户【客户名】，在供应商【供应商】下，有新的先采后付还款 XX 元，支付宝付款失败，请及时让客户支付宝余额或绑定银行卡充值，以免影响征信”，与 UI 一致

- **tc-P0-功能测试：易付通还款通知_情况二（已代付）_超3天代付触发与定时（正常）**
        - PC:1、准备超过还款日 3 天且支付宝已代付的记录，另备刚满第 3 天的对照记录；
2、绑定业务员账号可登录。
  - **在对照记录满第 3 天当日等待 8 点任务完成后查看待办**
          - 第 3 天不按“超 3 天”触发情况二通知

  - **将测试数据推进至自第 4 天起，等待 8 点任务完成后查看待办**
          - 符合自动代付条件的记录发送情况二通知，通知由对应日期 8 点任务生成，时间正确

- **tc-P0-功能测试：易付通还款通知_情况二（已代付）_接收人范围与当日多笔汇总（正常）**
        - PC:1、准备单供应商与联合销售主体下符合情况二的客户（均已绑定业务员）；
2、同一客户当日有多笔符合情况二的代付记录并已登记各笔金额；
3、相关业务员账号可登录。
  - **等待当日 8 点任务执行完成**
          - 任务正常完成

  - **分别以单供应商、联合销售主体绑定业务员账号打开待办消息**
          - 各业务员收到其绑定客户的情况二通知，接收人范围同情况一

  - **按该多笔客户与当日日期检索情况二通知数量并比对金额**
          - 同日代付汇总只发一条通知，通知金额等于当日各笔代付记录的合计

- **tc-P0-功能测试：易付通还款通知_情况二（已代付）_模板文案支付宝已代付（UI）**
        - PC:1、准备已发送的情况二通知及该客户对应代付记录；
2、接收业务员账号可登录。操作入口：用户端→待办消息→易付通还款通知。
  - **打开该情况二通知查看正文状态文案**
          - 正文含状态文案“支付宝已代付”，以红色强调

  - **核对正文整体模板**
          - 正文为“你的客户【客户名】，在供应商【供应商】下，有新的先采后付还款 XX 元，支付宝已代付，请及时让客户支付宝余额或绑定银行卡充值，以免影响征信”，与 UI 一致

- **tc-P1-功能测试：易付通还款通知_情况二（已代付）_状态流转与补扣（联动/异常）**
        - PC:1、准备一笔先满足情况一、后满足超 3 天代付的账单；
2、另备还款未扣但 3 天内补扣成功的账单；
3、保留业务员绑定关系，绑定业务员账号可登录。
  - **在该账单还款日 8 点任务完成后记录通知**
          - 该时点发送一条情况一通知，可追溯到该笔账单

  - **将数据推进至超 3 天且代付完成，等待对应 8 点任务**
          - 该时点再发送一条情况二通知，可追溯到同一笔账单

  - **对 3 天内补扣成功的账单，在原本可能触发情况二的日期任务完成后查看待办**
          - 不为该已补扣成功账单发送情况二通知

- **tc-P0-功能测试：易付通还款通知_通用_正文数据待办类型与消息通道（数据校验）**
        - PC:1、准备一条已发送通知及对应账单，登记客户名、供应商名与应还/代付金额；
2、接收业务员账号可登录；
3、具备查看测试通知发送记录的权限。
  - **打开通知正文依次核对客户名、供应商名、还款金额**
          - “你的客户【…】”“在供应商【…】下”与账单一致，“先采后付还款 X 元”与当日应还/代付金额合计一致

  - **使用接收业务员账号打开待办消息列表并检查类型名称**
          - 待办消息列表展示消息类型，易付通还款相关消息类型名称为“易付通还款通知”，对应消息正常展示

  - **核对站内待办与短信发送记录**
          - 生成站内待办消息，不发送短信

- **tc-P0-功能测试：易付通还款通知_通用_多主体接收人隔离（数据校验/异常）**
        - PC:1、准备单供应商、联合销售主体、联合分供应商下符合发送条件的客户及各自绑定业务员；
2、同一客户在销售主体和分供应商分别绑定不同业务员；
3、另备同一客户在主体甲未绑定、主体乙已绑定的场景；
4、各业务员账号可登录。
  - **等待 8 点任务执行完成**
          - 任务正常完成

  - **分别核对单供应商、联合销售主体、联合分供应商绑定业务员的待办**
          - 通知发给对应主体下该客户绑定的业务员，其他主体不混收

  - **核对同时归属销售主体与分供应商的客户两处业务员待办**
          - 两处绑定业务员均收到该客户通知，不因客户相同漏发任一主体

  - **核对主体甲未绑定、主体乙已绑定的场景**
          - 主体甲不发送该客户通知，主体乙已绑定业务员正常接收，甲乙彼此不阻塞

- **tc-P2-功能测试：易付通还款通知_通用_定时任务失败次日重试（异常）**
        - PC:1、仅在隔离测试环境并获授权设置一次可恢复的任务失败；
2、留存当日应发送清单。
  - **使当天 8 点定时任务执行失败并留存证据**
          - 任务失败，当天不发送通知，且不误报为发送成功

  - **恢复测试环境并等待第二天 8 点任务执行完成**
          - 环境恢复正常，任务正常执行

  - **按应发送清单核对通知**
          - 前一天未发送的清单在第二天 8 点重新发送
